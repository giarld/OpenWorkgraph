# OpenWorkgraph Web Client

独立 React / TypeScript / Vite 前端。产品仅有一套工作图编辑器：浏览器临时工作图和运行时中的正式工作图共用数据与编辑能力。左上角主菜单进入“我的工作图”（#workgraphs），在独立列表页选择运行时、项目及工作中/已归档/回收站范围，进行新建、导入、导出、重命名、删除与恢复。批量删除移入回收站。编辑器左侧仅显示节点预览与资产库；运行时管理保留在右侧面板。旧开发样例已移入测试夹具，不再通过产品 URL 或菜单提供另一套界面。

运行时配对、连接列表和运行时管理位于可收起的右侧边栏。

未关联运行时时会直接打开临时工作图，可创建多个工作图、重命名、编辑节点、连接、分组、撤销重做以及导入文件。工作图与文件 Blob 保存到独立 IndexedDB 数据库 `openworkgraph-temporary-canvases` 的 `canvases` 存储区；待恢复正文草稿使用 `openworkgraph:temporary:drafts:`，最近选择使用 `openworkgraph:temporary:selected`。刷新后恢复，清除站点数据会删除这些本地内容。

临时工作图禁用 AI 运行、运行时输入预览和保存到资产库。关联运行时不会自动上传临时工作图；运行时工作图断线后仍按原有规则只读，可切换存储位置继续本地编辑。

临时与正式工作图使用协议包中相同的 `GraphSnapshot`、`Node`、`Edge`、`GraphOperation` 和 `GraphBundle`。打开临时工作图，点击“复制到工作区”，选择已连接运行时及启用的目标工作区，再确认复制。节点、连线、分组、尺寸和引用文件将通过现有图包导入事务创建为正式工作图，自动打开复制结果，原临时工作图保留。目标创建新图、节点和资源身份，不依赖浏览器文件；复制不会启动 AI。响应丢失时“重试复制”沿用原快照和幂等键，切换会话后须先核对原结果。

用户导出的工作图文件为 `.workgraph.zip`。ZIP 根目录的 `workgraph.json` 保存工作图结构和资源元数据，`assets/` 保存资源原始字节；结构 JSON 不内嵌 Base64。导入仅接受该 ZIP 格式，解包后继续使用统一图包校验与原子导入流程。

导入时在目标项目全部工作图（包括归档和回收站）中检查同名。名称未占用时保持原名；冲突时依次使用 `原名 (1)`、`原名 (2)`，直到找到首个可用名称。浏览器临时工作图与运行时项目使用同一规则。

首次从仓库根目录运行 `npm ci` 和 `npm run build`，构建协议与运行时（Web 类型检查和集成测试引用这些产物），再在本目录运行：

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run test:e2e
npm run build
```

源码位于 `src/`，测试位于 `tests/`，生产构建输出到 `dist/`。浏览器测试使用 Chrome，自动启动开发运行时器，验收截图与性能数据写入 `../docs/validation/`。

参见[开发与接口交接](../docs/development/phase-1-web.md)、[项目说明与来源许可](../README.md)。
