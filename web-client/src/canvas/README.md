# Canvas integration

Canvas owns layout, hit testing, ports, selection and viewport interaction. App owns node content, node toolbar, composer, menus, asset import and run controls. Types come from ../domain/types.ts; no shadow domain model exists.

## Work Graph operation scheduling

GraphEditor owns one FIFO queue for structural, layout and body-save commands. Every action projects immediately over the latest confirmed snapshot; only the queue head sends a request. A batch uses one existing transactional /commands request (layout.move.positions, layout.resize.sizes, or multiple node.delete operations). GraphWorkspace must not add a separate geometry queue or disable unrelated edits while a command is pending.

Transient errors retry at most three total attempts with the same idempotency key and body. A revision conflict refreshes the confirmed snapshot before constructing a new request. A terminal failure discards the failed action and every later queued overlay; acknowledged operations and saved content remain. GET/SSE refreshes reapply pending overlays so older acknowledgements cannot erase newer intentions. An ambiguous network failure also attempts reconciliation with the Runtime. Project deactivation and disposal cancel queued promises; transient offline status permits already accepted commands to finish their bounded retries.

Body saves (including prompts) join the same queue. A structural action accepted while drafts exist waits for their saves; later actions stay behind that dependency. A failed save prevents deletion. Resource preparation retains its progress workflow, then placement joins the queue; multi-file uploads prepare all resources before one atomic placement command.

GraphHistory no longer computes inverse operations or stores browser-local undo deltas. Each Runtime command appends one graph-owned document version in the command transaction. Temporary graphs use the same semantics in IndexedDB. Undo/redo fences accepted submissions and draft saves, then sends a direction, expected cursor, revisions and idempotency key to /history. New graph edits are disabled during the fence. Versions restore stable node IDs and complete bodies; graph revisions and node content versions never rewind. An unknown history result must be reconciled with the original key before new edits. Runs remain outside the editable document history and establish a boundary. See [document history](../../../docs/development/workgraph-document-history.md).

## Public interface

Import Canvas and CanvasHandle from ./Canvas. Required props: graph, selectedIds, onSelect, renderNode. Passing adapter enables domain mutations; onMove/onResize/onConnect/onDeleteNodes/onDeleteEdge optionally override those mutations. onResize receives a complete world-space Rect so northwest resize can update x/y as well as width/height. The adapter must treat group resize as bounds-only, and pure group translation as moving its members.

renderNode renders only the body. Canvas renders node.title outside it. renderToolbar renders only for one selected node, at a constant screen size. renderPanel renders in world space below the node, centered with a minimum 600 world-unit width. Mark custom scrollable or editable content data-canvas-interactive or data-canvas-no-zoom; native inputs, textareas, selects, media controls, links and contenteditable are protected automatically. Capture selection does not prevent editor input.

onCreateMenu(world, screen) handles blank doubleclick and blank right-click. onOpenNode(node) handles node doubleclick. onConnectCreate(nodeId, world, screen, port) handles release of a connection onto blank canvas. Screen points are client coordinates. onImportFiles(files, world) and onPasteText(text, world) delegate content creation to App. onError receives adapter errors also displayed in the canvas.

viewport is optionally controlled using {x,y,k}; onViewportChange receives updates. Ref methods: fit(), locate(id), getViewport(), getVisibleWorldBounds(). locateNodeId requests node focus. focusPanelNodeId focuses combined node/composer bounds only when that id or canvas dimensions change; regular graph updates and manual pan/zoom do not refocus. It reserves 130px above, 110px below, 30px at the sides, plus 24 world units above the node title. Zoom never exceeds 1 during this focus operation.

Viewport navigation (locate, fit, composer focus, minimap click and origin reset) uses a 260ms cubic ease-out transition. Zoom buttons, range track clicks, keyboard range changes and 100% reset use 140ms transitions; dragging the range thumb updates directly without animation. Trackpad and wheel input update immediately so high-frequency gestures stay attached to the fingers. All three viewport coordinates interpolate together during animated navigation, keeping the zoom anchor, grid and minimap synchronized. onViewportChange and getViewport report the currently displayed position; the range thumb displays the requested target scale. Consecutive animated zoom inputs accumulate their target scale. New navigation starts from the current frame; canvas gestures, wheel/trackpad input, range dragging and minimap dragging interrupt animation and update immediately. Graph changes, unmount and external controlled viewport updates cancel pending frames. The system prefers-reduced-motion setting disables animation, including snapping an active transition to its target when the setting changes. The root data-viewport-animating attribute identifies transitions for geometry assertions.

F centers the selected nodes' combined bounds in the viewport at 100% zoom. It uses the 260ms navigation animation, works from non-editing node content even when that content stops key bubbling, and leaves text fields, controls and dialogs to handle their own keys.

Image, video, audio, document, preview and file node bodies first render when they intersect the Work Graph viewport. NodeViewport retains their last content tree and resources offscreen, defers host content updates until re-entry, skips hidden layout/paint, and pauses CSS animations and native media without changing media sources. useNodeViewport exposes activity to expensive previews: image thumbnail sizing stops offscreen, PDF page rendering pauses while completed pages remain reusable, HTML timers/animations pause, and Markdown defers shared context changes. Standalone previews and dialogs default to active. Coverage: ../../tests/browser/resource-viewport.spec.ts.

## Interaction and reference

CanvasHandle.getPlacementPosition(size) returns a node's world-space top-left position centered in the currently rendered viewport, using the live viewport and measured canvas size. GraphWorkspace forwards the handle through onCanvas so the asset library can place new nodes in view. Placement retries retain the originally prepared position.

canDropData(dataTransfer) and onDropData(dataTransfer, world) support application-owned drags onto the editable canvas background. File imports keep their separate onImportFiles path. GraphWorkspace accepts only a live asset drag matching its resource request, project and graph; RealApp centers the copied node at the dropped world point. The asset copy and node placement retain their original idempotency keys and coordinates on retries.

- Default dark theme, line grid at 48 world units, pan tool. Command/Space on macOS and Ctrl/Space elsewhere reverse the current select/pan tool. Middle drag pans; blank right drag pans as requested for OpenWorkgraph.
- Ctrl/Alt (Windows/Linux) or Command/Alt (macOS) + node drag snaps the dragged node's top-left to half-grid steps (24 world units), without nearby-node alignment or guides. Multiselection translates together using the grabbed node (or its selected group) as the anchor, retaining relative spacing. The same modifier + corner drag snaps resizing to half-grid steps while keeping the opposite corner fixed and respecting minimum dimensions; image Shift-resizing and proportional video resizing preserve the aspect ratio by snapping the primary axis. Pressing/releasing Ctrl/Command or Alt updates the preview even without pointer motion; release recomputes using the release coordinates and modifier, while lost capture retains the last preview state. Alt provides snapping without toggling multiselection or switching tools.
- Unmodified wheel and two-finger trackpad scrolling pan in both axes. Ctrl+wheel (including Chromium's macOS trackpad pinch) and macOS Command+wheel zoom at the pointer, clamped to .05..5, including over node editors and interactive content. Command+wheel uses 1.1^(-deltaY/100); macOS Ctrl+wheel/pinch uses 1.1^(-deltaY/50) for faster response. Nonpixel deltas normalize to pixels. Wheel input is immediate; unmodified editor wheel stays native. A nonpassive capture listener cancels browser zoom before nested handlers or early returns. data-canvas-no-zoom regions and active pointer gestures suppress both browser and work graph zoom. Chromium cannot reliably distinguish a macOS trackpad pinch from physical Ctrl+mouse-wheel, so both zoom the work graph at the same sensitivity.
- Select, modifier multiselect, intersecting box selection, Ctrl+A, Delete/Backspace and Escape are scoped away from editors. Ctrl+G/Shift+Ctrl+G delegate grouping to the adapter. Ctrl+Z/Shift+Ctrl+Z/Y use parent callbacks; no run-state snapshots are restored locally.
- Four 28px corner targets resize at a 220x160 minimum. Images/video preserve their starting aspect ratio; opposite corner stays anchored. Group movement previews members and commits each member only through its selected group, avoiding double translation.
- Groups are visual frames, never dependency endpoints. All content has output ports; text/image/execution have input ports. When onExecutionOutputs(nodeId, world, screen) is provided, execution nodes show an interactive folder output: clicking or dragging opens the application-owned hidden-output picker, never a reference connection or node-creation menu. Keyboard Enter/Space also opens it. Document and other delivery outputs attach directly to that folder. Body, port and 32-screen-pixel proximity drops follow the reference. Adapter remains authoritative for locks, graph scope and dependency validation.
- Cubic SVG edges use reference curvature max(abs(dx)/2,50), with a transparent 16px hit path. All edges render; node lookup is indexed once per render.
- Copy serializes selected node snapshots and internal input edges. Paste calls adapter.pasteNodes once at the viewport center. Output provenance edges are omitted. Group memberships map only explicitly selected snapshots. Asset cloning and atomic undo belong to the adapter.
- Minimap can be toggled and dragged. Zoom dock is 265x56 when App supplies its own tool dock; it includes a 5..500 slider, percentage/100% reset, fit, minimap and centered origin reset. showZoomButtons optionally adds plus/minus. Slider changes, plus/minus and 100% reset preserve the screen position of the selected nodes' combined bounds center; with no selected nodes, they anchor to the viewport center.
